---
title: Using it from an agent (the skill)
description: The agent skill is bundled in the aos binary and installs itself. An agent with a shell can then drive the machine, locally or over SSH, with no server running.
---

The agent skill is a short instruction file that tells an agent that aos exists, what its exit codes mean, and which commands need a screen. It is the main way an agent uses aos, and it needs no server.

## Example

The first `aos` command you run writes the skill to `~/.claude/skills/` and `~/.agents/skills/`. It is refreshed whenever the binary changes. To install it by hand, for example into a fresh home directory:

```sh
aos skill install
```

```sh
aos skill show        # print the skill without installing it
aos skill path        # print where it would be written
aos skill uninstall   # remove it
```

Set `AOS_NO_SKILL_AUTOINSTALL=1` to stop the automatic install.

## Why the skill is the first choice

An agent that can run shell commands can already run `aos`. The skill fills in what it does not know:

- **Nothing runs in the background.** No server, no port, no process to restart after a reboot.
- **It works over SSH.** The skill is instructions, not a connection, so it applies to any machine with the binary.
- **Every command is available.** Commands that run until interrupted, like `watch clipboard` and `remote share`, are left out of the MCP tool list. From a shell an agent can run them with `--max=1` or in the background.
- **The help is always current.** `aos commands --json` and `aos <group> --help` come from the installed binary.

Use [MCP](/aos/mcp/) when your agent wants typed tools with schemas instead of a terminal. Both paths run the same code.

## Driving another machine over SSH

```sh
ssh server aos system info
ssh server aos exec capture -- systemctl is-active nginx
ssh server aos file read /etc/hostname
```

Install aos on the far machine the same way as anywhere else:

```sh
ssh server 'curl -fsSL https://raw.githubusercontent.com/muthuishere/aos/main/install.sh | sh'
```

For MCP over SSH, keep `serve mcp` on loopback and forward the port:

```sh
ssh -L 14320:127.0.0.1:14320 server
```

The token is still required through the tunnel.

## What the skill tells the agent

Read it with `aos skill show`. In short:

- Ask the binary for help instead of guessing flags.
- Exit code `0` means it worked. `1` means it ran and failed, or refused on purpose. `2` means it refused before doing anything.
- `exec capture` runs a program, not a shell line. Use `exec shell` for pipes.
- `launch` passes unknown flags through to the app.
- `file delete` refuses filesystem roots and `$HOME`.
- Some commands run until stopped and never return on their own.

## Gotchas

- **A headless server refuses desktop commands.** `ssh server aos window list` exits 2 and says it needs a display. On Linux, `aos headless start --wm` provides one. See [headless machines](/aos/headless/).
- **The audit trail is per machine.** `ssh server aos obs audit --since=24h` shows what an agent did on that server, not on your laptop.
- **Agents reading this site** can use [`/aos/llms.txt`](/aos/llms.txt) and `llms-full.txt`, which hold the same documentation in one file.
