---
title: Headless machines
description: Most of aos works with no display. On Linux, headless start creates a virtual display for the commands that need one.
---

Most aos commands need no screen. On a server, in CI, or in a container, `exec`, `file`, `pkg`, `network`, `system`, `power`, `battery`, `font`, `debug` and `serve` work the same as on a laptop.

## Example

Check what this machine has:

```console
$ aos headless status
platform     linux
DISPLAY      -
WAYLAND      -
xvfb         present
managed      none

display      no — only the screenless commands will work
```

On Linux, start a virtual display and the desktop commands work:

```sh
aos headless start --size=1920x1080 --wm
aos window list
aos capture screenshot --out=/tmp/shot.png
aos headless stop
```

Later `aos` commands find the managed display on their own. There is no `export DISPLAY` step.

## Options for `headless start`

| flag | what it does |
|---|---|
| `--display=:99` | X display number to use |
| `--size=<WxH>` | screen size of the virtual display |
| `--wm` | also start a lightweight window manager, so windows can be placed and focused |

`headless start` waits for the window manager to claim the screen before it returns, so the next command does not race it.

## What a screenless machine says

```console
$ aos window list
aos: "window list" needs a display, and this machine has none
Start one with `aos headless start`, or check `aos headless status`.
```

The command exits 2 before doing anything. Agents get an error they can act on instead of a failure deep inside a display call.

## Know in advance what will work

```sh
aos headless status       # is there a display, and where did it come from
aos commands              # on a screenless machine, lists only what will run
aos commands --all        # `g` marks commands that need a display
aos commands --json       # each entry carries "needs_display"
aos serve mcp --gui=off   # offer an agent only the screenless tools
```

## Gotchas

- **`headless start` and `headless stop` are Linux-only.** macOS and Windows have no equivalent of Xvfb. There the desktop commands need a real logged-in session, and `headless status` says so.
- **An existing display always wins.** If `DISPLAY` is already set, aos uses it and never redirects a real session to the virtual one.
- **Xvfb must be installed** on the Linux machine. `aos headless status` shows whether it is present.
