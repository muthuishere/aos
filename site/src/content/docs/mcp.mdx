`aos serve mcp` turns every command on this machine into an MCP tool. Use it when your agent wants typed tools with schemas instead of a shell.

:::note
The [agent skill](/aos/agent-skill/) is the first choice. An agent with a shell needs nothing running to use `aos`, and that path works over SSH. MCP is the second way in.
:::

## Example

```console
$ aos serve mcp
aos mcp  http://127.0.0.1:14320/mcp
token           YOUR_TOKEN
tools           96
connect         claude mcp add --transport http aos http://127.0.0.1:14320/mcp \
                  --header "Authorization: Bearer YOUR_TOKEN"
```

Run the printed `claude mcp add` line to connect Claude Code. Every command available on this machine becomes one tool with the same summary, usage and examples as the CLI.

The tool name is the route with underscores. `window move` is `window_move`. A call with `{"app":"Chrome","zone":"1B"}` does the same work as `aos window move Chrome --zone=1B`.

## Options

| flag | what it does |
|---|---|
| `--addr=<host:port>` | where to listen. Default `127.0.0.1:14320` |
| `--token=<k>` | pin the token instead of minting one per run. At least 16 characters |
| `--groups=<a,b>` | expose only these groups |
| `--gui=on\|off\|auto` | whether to include tools that need a display. Default `auto` |
| `--quiet` | print less at start |

Preview the tool list without starting a server:

```console
$ aos serve tools --groups=window
window_arrange               Apply a saved layout of many windows in one pass
window_focus                 Bring a window to the front
window_list                  List open windows
window_move                  Move a window to a zone, a split, or absolute bounds
```

## The token

Loopback is not a permission. Every process on the machine can reach `127.0.0.1`, and this server drives windows, input and files. So each run mints a random token and refuses any request without it. Send it as an `Authorization: Bearer` header or a `?t=` query parameter.

Pin a token so a client configured once survives a restart:

```sh
export AOS_MCP_TOKEN=$(openssl rand -hex 16)   # or --token=…
aos serve mcp
```

## Give an agent less than everything

```sh
aos serve mcp --groups=window,capture,exec   # a subset
aos serve mcp --gui=off                      # only the screenless tools
```

With `--gui=auto`, tools that need a display appear only when the machine has one. A tool that cannot run is worse than no tool: the agent tries, fails, and tries again.

## Keep it running

```sh
aos service create mcp --autostart --now -- aos serve mcp
aos service status mcp     # exits non-zero unless it is running
aos service list
aos service remove mcp
```

This creates a launchd user agent on macOS, a `systemd --user` unit on Linux, or a Scheduled Task on Windows. Everything is per user, so no admin or sudo is needed. Pin a token first, or the client's token will stop matching after each restart.

## Over SSH

Keep the server on loopback and forward the port:

```sh
ssh -L 14320:127.0.0.1:14320 server
```

The token is still required through the tunnel, and it never crosses the network in clear text.

## Gotchas

- **A pinned token shorter than 16 characters is refused.**
- **Commands that run until interrupted are not tools.** `watch clipboard`, `watch window`, `watch file` and `remote share` are left out. Use them from a shell.
- **`--addr` on a non-loopback address sends the token in clear text.** Prefer an SSH tunnel.
- **The server does not sandbox `exec`.** If an agent should not run arbitrary commands, leave the `exec` group out with `--groups`. See the [safety model](/aos/safety/).
