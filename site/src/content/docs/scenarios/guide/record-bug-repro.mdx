**Goal.** A short video of the bug, plus a list of the exact steps, ready to paste into an issue.

<Shot name="bug-rec" alt="Recording the window while reproducing" caption="aos capture video start window --app=MyApp" />

## Commands

Record just the one window, with a time cap:

```sh
aos capture video start window --app=MyApp --max=2m --out=~/Desktop/bug.mp4
```

Reproduce it. Mark the moment:

```sh
aos mouse click --app=MyApp --find=Save
aos capture video mark "crash after Save"
aos capture screenshot --app=MyApp --out=~/Desktop/bug-state.png
aos capture video stop --raw
```

`--raw` skips the zoom render. A bug video should show exactly what was on screen.

Get the step list from the audit log:

```sh
aos obs audit --since=10m
```

<Shot name="obs-failed" alt="The failed commands from the last hour, for the report" caption="aos obs audit --since=1h --failed" />

## What to tell an agent

> Record the MyApp window while you reproduce the bug. Mark the moment it fails, take a screenshot, stop, and give me the video plus the commands you ran.

## Gotchas

- **`window` mode records one window.** If the bug involves a dialog that opens as a separate window, use `app --app=MyApp` to follow every window of that app, or `monitor`.
- **The marks are in the events file** next to the video, with timestamps.
- **`obs audit` lists routes and exit codes, not argument values.** Keep the argument values from the session if the report needs them.
- **Keep `--max` short.** It is a hard cap enforced by ffmpeg.
